# Content guidelines

## Voice
Second person, present tense, active voice. Say what the reader can do, not what the product can do.

## Headings
Sentence case. No trailing punctuation. Do not skip levels.

## Code samples
Every sample must run as written. Use `example.com` for hosts and `YOUR_API_KEY` for secrets. Show output when it is not obvious.

## Terminology
Use the glossary in `docs/glossary.md`. If a term is missing, propose it in the PR.
