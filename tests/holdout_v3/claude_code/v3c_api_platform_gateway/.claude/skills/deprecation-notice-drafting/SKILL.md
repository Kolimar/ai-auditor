# Drafting deprecation notices

Deprecation emails are read by integrators who may be mid-sprint and annoyed. Write something that respects their time and makes the migration obvious.

Gather first: what is being removed, the replacement, the removal date, and the number of affected customers if known. If the replacement is not equivalent, find out the gaps.

Structure: a subject line that names the endpoint and the date; one paragraph with what changes and when; a before/after request example; the exact steps to migrate; what happens if they do nothing; how to get help. For enterprise customers add a paragraph offering a call. Keep an honest tone, do not blame, and avoid hedging about the date.
